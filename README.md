# proxdump — encrypted Proxmox VE backups to cloud storage

**English** | [Français](README.fr.md) | [Español](README.es.md) | [Deutsch](README.de.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

`proxdump` backs up the virtual machines and containers of a **Proxmox VE**
node with `vzdump`, **encrypts** the archives on the server and uploads them
to **Microsoft OneDrive**, **Google Drive**, **Dropbox**, any
**S3-compatible storage** (Backblaze B2, Cloudflare R2, Wasabi, Amazon S3,
MinIO…) or an **SFTP server**. Everything is driven from menus in the
terminal; nothing has to be learnt about `rclone`.

![proxdump demo: backup of a container to OneDrive, restore under a new ID, configuration and appearance menus](docs/demo.gif)

*Recorded on a real node; the long transfers are sped up.*

## Highlights

- **Encrypted before it leaves the server**: the destination only receives
  unreadable data (XSalsa20-Poly1305, through `rclone crypt`). File names
  stay legible and carry an `.encrypted` suffix.
- **Five kinds of destination**, several at once: one archive is created,
  then uploaded to each destination selected.
- **Verified**: after each upload the remote copy is compared with the local
  archive by checksum.
- **Retention**: number of versions kept, global or per guest, applied after
  each backup.
- **Restore** under the original ID, under a new ID, or simple download of
  the decrypted archive. The archives are standard `vzdump` archives: they
  can also be restored without this tool.
- **Scheduling**: several schedules (daily or weekly, all guests or a
  selection, one or several destinations), each of which can be run at once.
- **Guided connections**: step-by-step authorization for OneDrive, Google
  Drive and Dropbox on a server without a web browser; simple forms for S3
  and SFTP.
- **Two interfaces**: a native one with colour themes, mouse and an animated
  progress window, or the classic `whiptail` dialogs.
- **Six languages**: English, French, Spanish, German, Chinese (simplified)
  and Russian, for the interface and the log.
- **Small footprint**: a bash script, `rclone`, `jq` and what a Proxmox VE
  node already ships.

## How it works

```
 guest (VM/CT)                  local staging folder                      destination(s)
┌─────────────┐   vzdump    ┌───────────────────────────┐   rclone   ┌──────────────────────┐
│ 100 web     │ ──────────> │ vzdump-qemu-100-….vma.zst │ ─────────> │ pve-backups/<node>/  │
└─────────────┘             │ plaintext, then deleted   │   crypt    │ ….vma.zst.encrypted  │
                            └───────────────────────────┘            └──────────────────────┘
```

For each guest: `vzdump` creates the archive in a temporary folder, `rclone`
encrypts and uploads it, the copy is verified, retention is applied, and the
temporary folder is deleted. `vzdump` decides what goes into the archive, so
the per-disk "Backup" setting of Proxmox VE is honoured.

## Destinations

| Destination | Connection | Good to know |
|---|---|---|
| Microsoft OneDrive | Authorization in a browser, token pasted on the server | 250 GB per file |
| Google Drive | Same, with an OAuth client of your own (free) | 750 GB uploaded per day |
| Dropbox | Authorization in a browser, token pasted on the server | 350 GB per file |
| S3-compatible storage | Access key, secret and bucket | Backblaze B2, Cloudflare R2, Wasabi, Amazon S3, Hetzner, OVHcloud, Scaleway, MinIO… |
| SFTP server | SSH key generated by the tool, or password | NAS, another server, rented storage |

## Requirements

- a Proxmox VE node (developed and tested on PVE 9 / Debian 13), root access;
- at least one destination with enough space;
- a local folder that can temporarily hold the largest archive;
- for OneDrive, Google Drive and Dropbox: a computer with a web browser and
  [rclone](https://rclone.org/downloads/), once, for the authorization.

## Installation

```bash
git clone https://github.com/Mrdindon/proxdump.git
cd proxdump
./install.sh
```

`install.sh` installs what is missing (`rclone` from its official package,
`jq`, `whiptail`, `curl`) and copies the tool to `/usr/local/bin/proxdump`.
To update: `git pull && ./install.sh`. To remove: `./install.sh --uninstall`
(the configuration is kept).

On a node without git, download the `.deb` package from the
[releases](https://github.com/Mrdindon/proxdump/releases) and install it with
`apt install ./proxdump_*.deb`.

## Getting started

Run `proxdump` as root, then in **Configuration**:

1. connect at least one destination;
2. define the encryption passphrase, and **record it outside the server**:
   without it the backups cannot be recovered;
3. check the local staging folder and the backup options.

Then **Back up virtual machines and containers** for a first backup, and
**Automatic scheduling** for the following ones.

## Command line

```bash
proxdump                                  # the menus
proxdump backup --all                     # every guest, every destination
proxdump backup --to s3,onedrive 100 101  # given guests and destinations
proxdump list                             # stored backups
proxdump prune                            # apply retention
```

## Limitations

- One node at a time: the tool backs up the guests of the node it runs on.
- Full backups only (no incremental, no deduplication).
- Local space for the compressed archive is needed, for backup and restore.
- The translations were not reviewed by native speakers: corrections are
  welcome.
