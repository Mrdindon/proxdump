# proxdump — зашифрованные резервные копии Proxmox VE в облачном хранилище

[English](README.md) | [Français](README.fr.md) | [Español](README.es.md) | [Deutsch](README.de.md) | [简体中文](README.zh-CN.md) | **Русский**

`proxdump` создаёт резервные копии виртуальных машин и контейнеров узла
**Proxmox VE** с помощью `vzdump`, **шифрует** архивы на сервере и
отправляет их в **Microsoft OneDrive**, **Google Drive**, **Dropbox**, любое
**S3-совместимое хранилище** (Backblaze B2, Cloudflare R2, Wasabi, Amazon
S3, MinIO…) или на **сервер SFTP**. Всё управляется через меню в терминале;
изучать `rclone` не требуется.

![Демонстрация proxdump: резервное копирование контейнера в OneDrive, восстановление с новым ID, меню настройки и внешнего вида](docs/demo.gif)

*Записано на настоящем узле; длительные передачи ускорены. Интерфейс показан на английском.*

## Возможности

- **Шифрование до отправки с сервера**: в месте назначения оказываются
  только нечитаемые данные (XSalsa20-Poly1305, через `rclone crypt`). Имена
  файлов остаются читаемыми и получают суффикс `.encrypted`.
- **Пять видов назначений**, можно несколько сразу: архив создаётся один
  раз, затем отправляется в каждое выбранное назначение.
- **Проверка**: после каждой отправки удалённая копия сравнивается с
  локальным архивом по контрольной сумме.
- **Хранение**: число хранимых версий, общее или для отдельных гостей,
  применяется после каждого резервного копирования.
- **Восстановление** с исходным ID, с новым ID или просто скачивание
  расшифрованного архива. Архивы — стандартные архивы `vzdump`: их можно
  восстановить и без этого инструмента.
- **Расписание**: несколько расписаний (ежедневно или еженедельно, все
  гости или выбранные, одно или несколько назначений), каждое из которых
  можно выполнить немедленно.
- **Пошаговые подключения**: авторизация OneDrive, Google Drive и Dropbox на
  сервере без веб-браузера; простые формы для S3 и SFTP.
- **Два интерфейса**: собственный, с цветовыми темами, мышью и анимированным
  окном хода выполнения, или классические диалоги `whiptail`.
- **Шесть языков**: английский, французский, испанский, немецкий, китайский
  (упрощённый) и русский — для интерфейса и журнала.
- **Минимум зависимостей**: сценарий bash, `rclone`, `jq` и то, что уже есть
  на узле Proxmox VE.

## Как это работает

```
 гость (VM/CT)              локальная промежуточная папка                   назначение
┌─────────────┐   vzdump    ┌───────────────────────────┐   rclone   ┌──────────────────────┐
│ 100 web     │ ──────────> │ vzdump-qemu-100-….vma.zst │ ─────────> │ pve-backups/<node>/  │
└─────────────┘             │ открытый, затем удалён    │   crypt    │ ….vma.zst.encrypted  │
                            └───────────────────────────┘            └──────────────────────┘
```

Для каждого гостя: `vzdump` создаёт архив во временной папке, `rclone`
шифрует и отправляет его, копия проверяется, применяется политика хранения,
и временная папка удаляется. Состав архива определяет `vzdump`, поэтому
параметр «Резервная копия» каждого диска в Proxmox VE учитывается.

## Назначения

| Назначение | Подключение | Полезно знать |
|---|---|---|
| Microsoft OneDrive | Авторизация в браузере, токен вставляется на сервере | 250 ГБ на файл |
| Google Drive | То же, с собственным клиентом OAuth (бесплатно) | 750 ГБ отправки в сутки |
| Dropbox | Авторизация в браузере, токен вставляется на сервере | 350 ГБ на файл |
| S3-совместимое хранилище | Ключ доступа, секрет и бакет | Backblaze B2, Cloudflare R2, Wasabi, Amazon S3, Hetzner, OVHcloud, Scaleway, MinIO… |
| Сервер SFTP | Ключ SSH, созданный инструментом, или пароль | NAS, другой сервер, арендованное хранилище |

## Требования

- узел Proxmox VE (разработано и проверено на PVE 9 / Debian 13), доступ
  root;
- хотя бы одно назначение с достаточным местом;
- локальная папка, способная временно вместить самый большой архив;
- для OneDrive, Google Drive и Dropbox: компьютер с веб-браузером и
  [rclone](https://rclone.org/downloads/) — один раз, для авторизации.

## Установка

```bash
git clone https://github.com/Mrdindon/proxdump.git
cd proxdump
./install.sh
```

`install.sh` устанавливает недостающее (`rclone` из официального пакета,
`jq`, `whiptail`, `curl`) и копирует инструмент в `/usr/local/bin/proxdump`.
Обновление: `git pull && ./install.sh`. Удаление:
`./install.sh --uninstall` (конфигурация сохраняется).

На узле без git скачайте пакет `.deb` со страницы
[релизов](https://github.com/Mrdindon/proxdump/releases) и установите его командой
`apt install ./proxdump_*.deb`.

## Начало работы

Запустите `proxdump` от имени root, затем в меню **Настройка**:

1. подключите хотя бы одно назначение;
2. задайте парольную фразу шифрования и **запишите её вне сервера**: без
   неё резервные копии невозможно восстановить;
3. проверьте локальную промежуточную папку и параметры резервного
   копирования.

После этого выберите **Резервное копирование виртуальных машин и
контейнеров** для первой копии и **Автоматическое расписание** для
последующих.

## Командная строка

```bash
proxdump                                  # меню
proxdump backup --all                     # все гости, все назначения
proxdump backup --to s3,onedrive 100 101  # указанные гости и назначения
proxdump list                             # сохранённые резервные копии
proxdump prune                            # применить политику хранения
```

## Ограничения

- Один узел за раз: инструмент копирует гостей того узла, на котором
  запущен.
- Только полные копии (без инкрементных копий и дедупликации).
- Для сжатого архива нужно локальное место — и при копировании, и при
  восстановлении.
- Переводы не проверялись носителями языка: исправления приветствуются.
